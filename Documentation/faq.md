# Часто задаваемые вопросы

## 1. Архитектурные решения

### Почему GameWorld реализован как синглтон?
**Ответ:**
- Удобный глобальный доступ из любых систем
- Упрощение управления жизненным циклом объектов
- Единственный источник истины для игрового состояния

## 2. Система сцен

### Почему GameHUD не отдельная сцена?
**Ответ:**
- Должен отображаться поверх игрового уровня
- Тесная интеграция с игровой логикой (здоровье, боеприпасы)
- Минимизация переключений контекста рендеринга

## 3. Генерация лабиринта

### Почему DFS вместо других алгоритмов?
**Ответ:**
- Гарантирует единственный путь (без циклов)
- Простота реализации
- Хорошо подходит для roguelike-игр
- Позволяет легко контролировать сложность через параметры

### Почему двухэтапное удаление объектов?
**Ответ:**
- Безопасность при итерации по объектам
- Избегание "висячих" указателей
- Возможность выполнить cleanup-логику
- Соответствие RAII принципам

## 4. Система ресурсов

### Почему централизованный менеджер?
**Ответ:**
- Единая точка доступа к ресурсам
- Избегание дублирования в памяти
- Автоматическое кэширование

## 5. Система статистик

### Почему std::any для хранения значений?
**Ответ:**
- Гибкость (поддержка любых типов)
- Простота добавления новых атрибутов
- Читаемость кода (не нужны шаблоны везде)
- Оптимально для редких изменений

## 6. Исключения

### Почему избегание исключений?
**Ответ:**
- Предсказуемость в реальном времени
- Проще отладка в игровом цикле
- Лучшая производительность
- Явная обработка ошибок через return codes
